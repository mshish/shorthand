# Implementation plan: Shorthand settings UI restructure

Spec: `docs/superpowers/specs/2026-08-17-shorthand-settings-ui-design.md`
Branch: `shorthand/settings-ui`, cut from `shorthand`.

The spec is the binding authority. Where this plan and the spec disagree, the
spec wins.

## Global Constraints

These bind every task. A violation is a defect regardless of whether the
task's own text mentions it.

1. **Delete nothing.** No component file is removed, no export is removed
   from `src/components/settings/index.ts`, no entry is removed from
   `SECTIONS_CONFIG`. Hiding is achieved by a predicate returning false.
2. **Move nothing.** No component changes path. Fork-only sections import
   components from where upstream already keeps them.
3. **Do not edit upstream files beyond the eight named in the spec.** Those
   are `Sidebar.tsx`, `App.tsx`, `about/AboutSettings.tsx`, `settings.rs`,
   `shortcut/mod.rs`, `lib.rs`, `settingsStore.ts`, and the 24 locale files.
   `bindings.ts` is regenerated, never hand-edited. Touching any other
   upstream file is a defect — raise it instead.
4. **No bare string literals in JSX.** `eslint-plugin-i18next`'s
   `no-literal-string` is enforced in CI. All user-visible text goes through
   `t()`.
5. **All 24 locales or none.** `bun run check:translations` exits non-zero if
   a key exists in `en` and not in the other 23. New keys are added to all 24
   files with the English string as the value in every one. The locales are:
   `ar bg cs da de en es fr he hi it ja ko ne nl pl pt ru sv tr uk vi zh
   zh-TW`.
6. **Fork-only code lives under `src/shorthand/`.** The `@/` alias already
   resolves `src/*`; no build config change is needed.
7. **Rust changes must pass `cargo fmt --check` and add no new
   `cargo clippy` warnings** in the files touched.
8. **Do not change existing tests.** If an existing test fails, that is a
   signal the change reached further than intended — report it rather than
   editing the test.
9. **Commit per task**, conventional-commit style, with the trailers used by
   recent commits on this branch.

## Task 1 — Add the `show_all_settings` setting end to end

Add a fork-only boolean setting, default `false`.

`src/bindings.ts` is generated by tauri-specta and carries a do-not-edit
header. It is emitted from `lib.rs` under `#[cfg(debug_assertions)]`.
Regenerate it with a debug build; do not hand-edit it.

Thread it exactly the way `show_tray_icon` is threaded. Read that setting's
full path through the codebase first and mirror it.

1. `src-tauri/src/settings.rs` — add `show_all_settings: bool` to the
   settings struct, following the house style used by neighbouring booleans.
2. `src-tauri/src/settings.rs` — add it to the `get_default_settings()`
   literal with value `false`.
3. `src-tauri/src/shortcut/mod.rs` — add a
   `#[tauri::command] #[specta::specta]` setter named
   `change_show_all_settings_setting`, mirroring the neighbouring setters.
4. `src-tauri/src/lib.rs` — register that command in the `collect_commands![…]`
   list.
5. Run a debug build so `src/bindings.ts` regenerates. Commit the regenerated
   file.
6. `src/stores/settingsStore.ts` — add a `show_all_settings` entry to
   `settingUpdaters`.

Step 6 is not optional. Without an updater, `updateSetting` logs
"No handler for setting" and the toggle appears to work, then reverts on
reload.

**Verification:** `cargo test` passes, including the v0.9.0 settings fixture
test (it survives because the struct carries `#[serde(default)]`).
`bun run build` succeeds. Confirm `show_all_settings` appears in the
regenerated `src/bindings.ts`.

## Task 2 — Default `paste_method` to `None`

`src-tauri/src/settings.rs` — change `impl Default for PasteMethod` to return
`PasteMethod::None` on all platforms.

This is the change that makes the whole UI restructure safe.
`src-tauri/src/actions.rs` calls `utils::paste(final_text, …)` unconditionally
when a transcription completes with non-empty text, and `PasteMethod::None`
is the only value that skips keystroke injection. Without this, hiding the
paste settings ships a product that types a meeting transcript into whatever
window has focus, with the off-switch removed from the UI.

Do not delete the other `PasteMethod` variants or any paste code. They remain
reachable through the escape hatch.

Leave a comment at the changed default recording the actual reason: this fork
streams transcripts to followers rather than delivering them to the focused
window, so keystroke injection is off by default. State the reason, not a
proxy for it.

**Verification:** `cargo test` passes. Existing stored settings are unaffected
— serde only applies a default when the field is absent.

## Task 3 — Locale keys for the three new sections

Add sidebar label keys for the fork-only sections to **all 24** locale files
at `src/i18n/locales/<locale>/translation.json`, with the English string as
the value in every locale. This matches how the fork already added
`systemAudio` and `followStream`.

Keys, alongside the existing `sidebar.*` entries:

- `sidebar.capture` → `"Capture"`
- `sidebar.transcription` → `"Transcription"`
- `sidebar.app` → `"App"`

Also add, next to the other About strings, the escape-hatch row used in
Task 6:

- `about.showAllSettings.label` → `"Show all Handy settings"`
- `about.showAllSettings.description` → `"Reveal every setting from upstream Handy, including features Shorthand hides."`

Place each key so the file's existing structure and ordering convention is
preserved. Do not reorder or reformat unrelated entries — a reformatted
locale file is a 24-file merge conflict.

**Verification:** `bun run check:translations` passes.

## Task 4 — Visibility registry and Sidebar filtering

Create `src/shorthand/visibility.ts` as the single source of truth for
section visibility, and have `Sidebar.tsx` and `App.tsx` consult it.

`SECTIONS_CONFIG` in `src/components/Sidebar.tsx` already gives every section
an `enabled: (settings) => boolean` predicate, and the sidebar filters on it
at the `Object.entries(SECTIONS_CONFIG).filter(...)` call. Compose with that
predicate rather than replacing it — `postprocessing` and `debug` rely on
their existing predicates, and `debug`'s is what keeps the Ctrl/Cmd+Shift+D
toggle in `App.tsx` working.

The registry exports:

- the set of upstream section ids hidden in simplified mode:
  `general`, `models`, `advanced`, `postprocessing`
- the set of fork-only section ids hidden when `show_all_settings` is true:
  `capture`, `transcription`, `app`
- a predicate taking a section id and the `show_all_settings` value, applying
  both sets

In this task the fork-only sections do not exist yet, so only the first set
has any effect. Write the registry to handle both from the start; Task 5
registers the sections.

`App.tsx` must also be corrected. It hardcodes
`useState<SidebarSection>("general")` for the initial section, and
`renderSettingsContent` falls back to `SECTIONS_CONFIG.general.component` for
an unknown section. Both would resolve to a section simplified mode hides,
opening the app on a page absent from the sidebar. Both must resolve to a
section that is currently visible.

**Verification:** `bun run build` and `bun run lint` pass. In a debug build
with default settings, the sidebar shows only History (if enabled), Debug (if
`debug_mode`), and About — `general`, `models`, `advanced` and
`postprocessing` are gone, and the app does not open on a blank or hidden
section.

## Task 5 — The three fork-only sections

Create three components under `src/shorthand/` and register them in
`SECTIONS_CONFIG`.

Every component listed below already exists. Import each from its current
path; do not move or copy any of them. Read
`general/GeneralSettings.tsx` and `advanced/AdvancedSettings.tsx` first and
follow their structure — `SettingsGroup` wrappers, prop passing, and any
conditional rendering a component depends on.

**Capture** — transcribe shortcut and cancel shortcut (carry the existing
Linux/push-to-talk conditional from `GeneralSettings.tsx` rather than
dropping it), `PushToTalk`, `MicrophoneSelector`, `ChannelSelector`,
`SystemAudioCapture`, `SystemAudioDeviceSelector`, `MuteWhileRecording`,
`VoiceActivityDetection`, `ShowOverlay`, `FollowStreamOutput`.

**Transcription** — `ModelsSettings` (the model catalog), `ModelSettingsCard`
(language and translate-to-English; it lives under `settings/general/` and
self-hides when the active model lacks the capability — that behaviour must
survive), `CustomWords`, `FillerWordRemoval`.

**App** — `AutostartToggle`, `StartHidden`, `ShowTrayIcon`, `AudioFeedback`,
`VolumeSlider`, `OutputDeviceSelector`. `VolumeSlider` and
`OutputDeviceSelector` are gated on audio feedback being enabled in
`GeneralSettings.tsx`; preserve that gating.

Register all three in `SECTIONS_CONFIG` with `labelKey` values
`sidebar.capture`, `sidebar.transcription`, `sidebar.app`, icons from
`lucide-react` consistent with the existing choices, and `enabled: () => true`
— visibility is the registry's job, not the predicate's.

Order the sidebar so the fork-only sections come first, matching the spec's
pipeline order: Capture, Transcription, App, then History, Debug, About.

**Verification:** `bun run build` and `bun run lint` pass. In a debug build:
all three sections render with their listed contents; push-to-talk, the
microphone selector and follow-stream output are all present in Capture;
`ModelSettingsCard` still self-hides for a model without the capability.

## Task 6 — The escape-hatch row in About

Add a toggle for `show_all_settings` to
`src/components/settings/about/AboutSettings.tsx`, using the
`about.showAllSettings.*` keys from Task 3 and following the pattern of the
existing toggle in that file (`ShowWhatsNewOnUpdate`).

It goes in About specifically because About renders in both modes, so the
hatch can always be switched back off. A fork-only section would become
unreachable once the flag was enabled.

**Verification:** `bun run build` and `bun run lint` pass. In a debug build:
toggling it on shows upstream's seven sections and hides Capture,
Transcription and App; toggling it off restores the simplified six. Restart
the app and confirm the value persisted — this is what catches a missing
`settingUpdaters` entry from Task 1.
